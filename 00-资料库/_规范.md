# 资料库规范（Evidence Protocol）

> 适用项目：AI 口播数字人 — 产研实习合作提案
> 建立日期：2026-09-29
> 目的：所有资料必须可溯源、可分级、可被面试/合作方当场质疑时自证。

---

## 1. 证据等级（Evidence Tier）

| 等级 | 含义 | 允许的来源类型 |
|---|---|---|
| **A** | 一手权威事实 | 官方代码仓库、官方技术报告、论文原文（arXiv/期刊）、标准/监管文件、政府或研究机构公告、上市公司财报/官方新闻稿 |
| **B** | 可信二手 | 权威媒体报道（36氪、界面、每经、新浪财经、路透/彭博）、行业白皮书（IDC/艾瑞/QuestMobile，须能核到发布方）、学术机构博客 |
| **C** | 线索（未核验） | 自媒体、营销号、公司市场稿、社区帖子、论坛数据、无法定位原始出处的数字 |

**铁律**
- C 级内容**可以写进资料库**，但必须显式标注 `⚠️ 未核验`，**不得**出现在 PPT 结论页、不得作为方案收益承诺的依据。
- 任何数字若只在 C 级出现，PPT 里只能写"待核验"或直接删掉。
- 媒体若转述了公司官方发布（如"罗永浩数字人 GMV 5500 万"），优先追到**公司官方发布/财报/发布会**，追到则升 A，追不到保留 B。

## 2. 来源类型标签（Source Type）

`官方仓库` `论文原文` `官方技术报告` `监管文件` `上市公司公告/财报` `公司官网/新闻稿` `权威媒体` `行业白皮书` `学术博客` `自媒体/营销号` `社区讨论`

## 3. 条目格式（每条资料必须严格遵守）

```markdown
### [E-A-07] 技术名
- **事实**：一句话可验证陈述（避免"很好用""行业领先"这类不可验证表述）
- **来源类型**：官方仓库
- **证据等级**：A
- **来源**：
  - URL: https://github.com/xxx/yyy
  - 发布/更新日期: 2026-05-01（查不到写"未标注"）
- **支撑细节**（可选）：来自原文的原文引用/关键数字
- **我的推断**（如无则写"无"）：明确用"推断"二字开头，不得混入事实句
- **可用于 PPT**：✅ / ❌（为什么）
```

## 4. 硬性要求

1. **必带 URL + 日期**。抓不到原文就降级并说明。
2. **不得把营销话术当事实**。"全球首个""行业领先"这类表述只能出现在"厂商宣称"字段，且必须标明是厂商自述。
3. **不得编造**。查不到就写"未找到公开来源"，不要用记忆里的数字冒充。
4. **区分事实与推断**：每个结论后面标 `[事实]` 或 `[推断]`。
5. **日期敏感**：本项目涉及的 AI 视频/数字人模型迭代极快，超过 6 个月的数据标注为"可能过时"。
6. **许可证/成本信息必须标注日期**，因为开源模型 API 价格与开源协议变动频繁。

## 5. 目录约定

```
00-资料库/
  _规范.md                 ← 本文件
  01-数字人/               ← 数字人技术、模型、产品、监管
  02-AI视频/               ← 视频生成模型/产品
  03-数字人房产中介案例/    ← 落地案例（房地产/看房/讲解）
  04-其他相关资料/         ← 3D 建模、房产科技、工作流、成本测算
03-来源索引/               ← 全库来源清单（URL/日期/等级/被引条目）
index.html                 ← 可检索展示页
```

## 6. 实验/数字类信息额外要求

若资料涉及"效果提升 X%""成本降低 Y%"，必须在 PPT 附录注明：
- 该数字的**测试条件**（谁的测试？什么模型？什么输入？）
- 是否**有独立第三方复现**
- 属于 **厂商宣称** 还是 **独立测评**
