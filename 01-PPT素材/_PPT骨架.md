# PPT 骨架大纲

> 用途:与公司洽谈产研实习合作的提案 PPT
> 目标:证明"我做过扎实调研、懂技术边界、知道实习能交付什么"
> 核心策略:**不吹技术,不画大饼,用可核验的事实和清晰的边界赢得信任**

---

## 全局设计原则

### 三条底线
1. **凡数字必带来源与日期。** 被问"这个数哪来的"要能立刻答出。
2. **主动暴露风险。** 许可证问题、技术边界、不能承诺什么 —— 主动说比被问出来强。
3. **区分事实与推断。** 页面上用视觉区分,别混在一起。

### 预期对方会问的四个问题(提前准备答案)
| 问题 | 回答锚点 |
|---|---|
| "开源方案那么多,为什么要你做?" | 已有方案有许可证坑 + 缺房产场景的管线整合(P8) |
| "3-6 个月你能做出什么?" | 评测集 + 基线对齐 + 端到端 demo,不承诺算法创新(P13) |
| "这东西现在就能上线吗?" | 不能,合规链路(肖像授权/标识/备案)是前置条件(P6) |
| **"贝壳如视不是已经有了吗?"** | ⚠️ **最高频、最难答的问题。** 答案:如视是预生成文案播报,我们做的是"数字人在 3D 场景里指着墙说话"——叙事与空间绑定,这是如视没有的(P9) |

### ⚠️ 三个必须先知道的竞品事实(写 PPT 前必读)
1. **CinemaTraj**(arXiv:2607.26910, 2026-07-29)几乎逐字命中需求 2,**不要把运镜思路当原创卖点**
2. **贝壳如视 2019 年就有 AI 讲房**(收听完成率 73.8%,VR 房源 118 万套),**需求 1 不是新东西**
3. **Sora 2 官方自述在"镜头运动编排"上有困难且输入上限两张图**,**这是"不用端到端视频"最有力的论据,且是厂商自证**

### P6 合规:不是加分项,是前置条件 ⭐ 体现成熟度

## 第三段:数字人技术 + 引出需求(5-6 页)

### P7 数字人技术现状:分层格局
**三层分工**(一句话讲清):
```
底层 唇形替换   MuseTalk / Wav2Lip / LatentSync   ← 只改嘴,保留原视频
中层 肖像驱动   Hallo / Sonic / EMO              ← 单图 → 整脸动态
上层 全身生成   OmniHuman                          ← 单图+音频 → 全身
```

**实时性只有一条路**:MuseTalk 官方称 V100 上 30fps+,且非扩散模型(单步隐空间 inpainting),4GB 显卡可跑。但官方自述三项局限(256×256、胡须/唇色保留不佳、单帧抖动)。

### P8 ⚠️ 许可证:这个赛道最大的坑 ⭐ 差异化页
**标题建议**:"那些看起来免费的开源方案,商用时都有坑"

**数字人侧**:
| 方案 | 归属 | 许可 | 商用风险 |
|---|---|---|---|
| **MuseTalk** | 腾讯音乐娱乐 Lyra Lab | MIT + 模型可商用 | ✅ |
| **LatentSync** | 字节跳动 | Apache-2.0 | ✅ |
| **LiveTalking** | — | Apache-2.0 | ✅ |
| LivePortrait | 快手 | 代码 MIT,**InsightFace 模型仅限非商业研究** | ⚠️ 须换检测模型 |
| HeyGem/DUIX | 硅基智能 | 非标准社区许可 | ❌ **MAU>1000 强制商业授权** + 强制署名 |
| Wav2Lip | — | **无 LICENSE 文件** | ❌ 未授权状态 |
| RobustVideoMatting | — | GPL-3.0 | ❌ copyleft 传染风险 |

**视频模型侧**:
| 模型 | 许可 | 限制 |
|---|---|---|
| **Wan2.2 / Wan2.1** | Apache-2.0 | ✅ 真可商用(唯一无障碍旗舰开源) |
| HunyuanVideo-1.5 | 腾讯混元社区许可 | ⚠️ **排除欧盟/英国/韩国** |
| HunyuanVideo(初版) | **无 LICENSE 文件** | ❌ 不可推定 |
| LTX-2.x | 社区许可 | ⚠️ **年营收 ≥$10M 须付费许可**,违约须 30 天内补交 |
| 3DGS / instant-ngp / COLMAP / Open3D | 字段均 `NOASSERTION` | ❌ 需法务逐个核对 |

> **这页的价值**:多数竞争者会说"用开源方案就行"。你指出坑在哪,反而显得你真做过功课。
> ⚠️ GitHub 的 license 标签**不可信**——腾讯与 LTX 都返回 `NOASSERTION`,必须读 LICENSE 原文。

### P9 用户需求 → 技术落点 ⭐ 承接页
**先说为什么不用端到端 AI 视频**(厂商自证,极有力):
> `[事实]` OpenAI 官方文档自述 Sora 2 难以处理 `precise time-based event sequencing such as camera movement`(精确的时序事件编排,如镜头运动),且**输入上限为两张图**;而房产讲解恰恰要求空间准确 + 覆盖完整 + 运镜可控。
> `[事实]` 另有 CamCtrl3D(3DV 2025)证明"给定轨迹生成视频"可行 —— 但**我们已有 3D 模型,直接用引擎离线渲染即可,根本不需要生成模型**。

**需求 1 数字人口播** — 技术成熟,不是新东西
- 已有先例:贝壳如视(见 P5.5)
- 建议定位为**载体**而非独立产品:价值在"**它指着这面墙说这句话**"
- 数字人做**讲解员**不做销售:房产是高信任决策场景,"明显的 AI 脸做销售"会反噬信任

**需求 2 用公司 3D 资产讲房** — 技术内核是**相机路径规划**
- 输入:3D 场景 + 讲解音频
- 输出:无穿模、不漏房、节奏踩准语音的相机轨迹
- 四约束:覆盖性 / 可行性 / 节奏性 / 可编辑

**语音对齐不用自研** `[事实]`:Azure TTS 官方 SSML 支持 `bookmark`(词级 offset/duration)与 `viseme`;WhisperX(BSD-2-Clause,★24,294)提供词级时间戳

### P9.5 ⚠️ 已有同方向研究:CinemaTraj(诚实的页)
**标题建议**:"这个思路已经有论文了 —— 所以我不打算从零开始"

| CinemaTraj(arXiv:2607.26910,2026-07-29) | 与我们的关系 |
|---|---|
| LLM agent + 结构化 3D 场景图 | 可复用的系统设计蓝本 |
| 讲解意图 → 原子运镜(dolly/orbit/crane/pan/tilt/zoom/arc) | 对应我们的约束 C |
| 参数化轨迹 + 碰撞避免优化 | 对应我们的约束 A |
| 同步旁白与字幕对齐相机运动 | 对应我们的约束 D |
| 摘要原句:`real-estate advertising to virtual tour creation` | **几乎逐字命中需求 2** |

> **为什么主动放这页**:`[推断]` 对方大概率会自己查到这篇。你先说,显得你读过前沿文献且知道边界。**这比"我们有个独创思路"可信一百倍。**
> 顺势带出:正因为有顶会基线可复现可对比,实习的价值在**落地管线 + 垂直评测集**,不在发明算法。

## 第四段:规划(5-6 页)

### P10 技术架构图 ⭐ 提案核心页
```
[公司提供] 3D 房屋模型
     ↓
A 资产接入标准化 → B 户型语义解析 → C 话术生成(LLM,受数据约束)
     ↓
D TTS + 数字人驱动 → E 数字人入镜 → F 相机路径规划 ⭐ → G 渲染合成 + 合规标识
```

**待与公司确认的分叉点**(画成虚线备选):
- 场景来源:干净网格 vs 3DGS 点云 → **决定 F 的难度差一个量级**
- 数字人入镜:2D 图层 vs 3D 角色
- 渲染:实时引擎 vs 离线渲染

### P11 人员安排
诚实说明:
- **1 人 × 3-6 个月**能做什么
- 关键:说清**不需要**多少人做什么 —— 避免对方以为你要拖很多人

### P12 时间线
分阶段,每阶段有**可验收产出**(不是"完成 X 模块"这种)

**关键设计:里程碑按风险递增切分,即使最后一步做不深,前面也能独立构成完整交付**

| 阶段 | 产出 | 验收标准 | 风险 |
|---|---|---|---|
| 0 | 技术预研 + **许可证核查** | 选型报告 + 法务确认清单 | 低 |
| 1 | **M1 规则+样条端到端** | 跑通"讲稿分段 ↔ 镜头切换"全流程 | 低 |
| 2 | **M2 子模优化覆盖最大化** | 全屋覆盖、不重复覆盖,量化验证 | 低 |
| 3 | 评测集 + 基线对齐 | 与 COLMAP/官方 3DGS 的 PSNR/SSIM/LPIPS 对比 | 中 |
| 4 | **M3 LLM agent 运镜**(可选) | 从讲解稿自动生成运镜意图 | **高,做不深可放弃** |

> `[推断]` 这个切分是本提案最重要的风险设计:**M1+M2 本身就是一个完整、可演示、有价值的交付**,M3 是加分项而非前提。

### P13 成果定义 ⭐ 诚实的页更有说服力
**能承诺**:
1. 端到端 demo(nerfstudio 等 Apache-2.0 框架,跑通"3D 场景 + 数字人口播")
2. **房产 3D 评测集** —— 最被低估但对双方最有价值
3. 基线量化对齐(PSNR/SSIM/LPIPS + 训练时长 + 显存峰值)
4. 相机路径规划分级实现(M1 规则 → M2 子模优化 → M3 LLM agent)
5. **许可证核查报告 + 法务确认清单** —— 真实交付物,对公司有实际价值
6. 技术报告 + 开源仓库

**不能承诺**(主动划线,每条都给依据):
- ❌ 从零训练辐射场/视频生成基础模型
  - 依据:3DGS 官方仓库 24,021 stars / **713 open issues**
- ❌ 把"提出 CinemaTraj 式运镜思路"当原创贡献
  - 依据:arXiv:2607.26910,2026-07-29,已是公开研究
- ❌ 具体交付天数
  - 依据:复现耗时无法核验,不拍脑袋
- ❌ 直接可上线的商业产品
  - 依据:合规链路(肖像授权/标识/备案)是前置条件
- ❌ 承诺数字人合成质量
  - 依据:合成章节是全库证据最薄弱的一环,未找到官方文档或论文

> **这页是加分项不是减分项。** 每一条"不能承诺"都带可核验依据,比空口保证可信。

### P14 成本
算力不是瓶颈 —— 这是反直觉的论点,值得单独一页

| 项 | 数据 |
|---|---|
| RTX 4090 租用 | $0.34/h |
| 重建一套户型 | ≈ $34 |
| 6 个月总 GPU 费 | 百美元级 |
| 对比:1 名实习 6 个月人力成本 | 高出 1-2 个数量级 |

⚠️ 国内大厂 H100 无公开报价(需登录控制台),第三方比价数据不可用

**两个成本量级的对比**(说明为什么不做端到端视频生成):

| 路线 | 单分钟成本量级 | 依据 |
|---|---|---|
| 调 AI 视频 API | **$5–25** | Veo 3.1 $0.05–$0.40/秒;Gemini Omni Flash ≈$0.10/秒;Seedance ≈1 元/秒 |
| 自部署视频模型 | **25–60 GPU 小时** | Wan2.1 官方 README:RTX 4090 生成 5 秒 480P 需约 4 分钟 |

`[推断]` 日更房产内容用自部署视频模型不成立;但**3D 场景离线渲染是渲染不是生成**,成本量级完全不同。

**核心论点**:降的是**每套房产的边际内容成本**,不是一次性投入。建模是公司已付的一次性成本,管线建好后每套新房复用,边际成本趋零。
